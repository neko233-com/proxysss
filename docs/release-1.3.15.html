v1.3.15 双核调度、静态 sendfile 分界与 Linux 2C2G 对照

2026-11-22 用户要求继续优化 proxysss、修复不合理点，在 Debian 12 与 Ubuntu 24.04 LTS 上快速验证，并希望在 2C2G 限制下总体性能高于 nginx；全部落地后按既有授权直接发布。v1.3.15 只调整 Linux 双核明文 HTTP 调度、small 静态对象分界和对应测试夹具，不改变协议语义。

双核调度修正

  • 仅 Linux、性能模式启用、数据核预算为 2、traffic_profile: small 时，明文 HTTP 使用每核 pinned 单线程 runtime；1 核与 3 核及以上保留共享 runtime。
  • 每个 runtime 建立两个 SO_REUSEPORT 接受队列，总计四个，降低长连接 hash 放置方差；不增加 runtime 数。TLS accept worker 与明文 accept 解耦。
  • 实测 2 队列与 8 队列都更差，未采用；balanced/bulk 既有规则不变。

small 静态 32 KiB sendfile 分界

  • 小于 32 KiB：有界正文缓存 + 预构建 HTTP/1 keep-alive 完整响应。
  • 大于等于 32 KiB：完整 GET 在 HTTP owner 内同步 sendfile，保留版本锚点、fd 池、EAGAIN 背压和 TCP_CORK；不启用大文件 reactor。
  • sendfile 空闲 fd 池按每个数据核 32 个、最高 256 个预留；双核容量 64，覆盖 64 条并发 keep-alive 的 64 KiB 静态请求。

Linux 2C2G 最终对照

Ubuntu 22.04.5 LTS，Intel Xeon 6986P-C，nproc=2，cgroup cpu.max=200000 100000，单个网关进程用 prlimit --as=2147483648 限制 2 GiB 地址空间；nginx 1.28.0 源码构建，2 worker、reuseport、sendfile、open_file_cache、upstream keepalive 128、默认 proxy_buffering。两侧同一后端与 Go 负载器，64 条预连接、2 秒预热 + 5 秒测量、3 轮交替顺序，每请求校验状态与正文长度，共 2,888,924 次成功响应、0 错误。
