Beginner path

最小可用配置

这页先给你生产形态的最小配置，再解释为什么它应该落在这个能力面，而不是别处。

第一个站点

最小反向代理

适合先把 app.example.com 代理到本机服务，确认域名、监听端口和上游路径都正常。

http:
  plain_bind: 0.0.0.0:80

services:
  reverse_proxy:
    routes:
      - name: app
        hosts: [app.example.com]
        path_prefix: /
        upstream: http://127.0.0.1:9000
正式上线

只填域名就把 WebSocket 升为 WSS

只填写域名即可启用免费的内建 ACME：默认正式 Let's Encrypt + TLS-ALPN-01 + ECDSA P-256，只要求 A/AAAA 指向网关且公网 443 可达，不需要 certbot、acme.sh、DNS API 或账号邮箱。极老旧客户端可设置 http.tls.acme.key_algorithm: rsa2048；显式 challenge: http01 仍兼容，需要公网 80。

http:
  plain_bind: 0.0.0.0:80
  tls_bind: 0.0.0.0:443
  tls:
    auto_https:
      domains: [app.example.com]

services:
  domain_routes:
    - name: game-wss
      domains: [app.example.com]
      path_prefix: /ws
      upstream: ws://127.0.0.1:9000
官网 + API

静态资源和 API 按路径分开

以下配置在 /assets 分发资源，api.example.com 的 /api 转到后端并去掉前缀。static_sites[].hosts 可按域名隔离静态根目录，省略或空数组接受所有 Host；目录字段是 root。

http:
  plain_bind: 0.0.0.0:80

services:
  static_sites:
    - name: homepage
      hosts: [www.example.com]
      path_prefix: /assets
      root: ./www
      index_files: ["index.html"]

  reverse_proxy:
    routes:
      - name: api
        hosts: [api.example.com]
        path_prefix: /api
        upstream: http://127.0.0.1:8080
        strip_prefix: true
Choose the surface

选择对应的配置项

proxysss 把通用网关能力拆成多个清晰配置面。先选对面，再谈字段。

配置面 适用场景 不要误用成
services.reverse_proxy.routes
最常用 HTTP 代理面		 网站、API、后台系统、SSE、WebSocket、HTTP/2 gRPC、下载站。 不要把所有业务逻辑都塞进脚本替代它。
services.domain_routes
域名与路径代理		 按 domains 与 path_prefix 转发到 upstream，并可设置路由证书策略。 不支持嵌套 routes 或 service: static:... 引用。
services.ai_proxy
AI / SSE / OpenAI-compatible		 New API、OpenAI-compatible、SSE 流式输出、长响应代理。 不要把所有 HTTP 请求都默认塞进 AI proxy。
services.static_sites
静态文件分发		 官网、文档站、资源分发、CDN 回源、预热缓存、条件请求、Range 下载。 不要为了分发静态资源先写一层脚本。
services.service_discovery
Consul / etcd / Nacos		 把注册中心服务映射到 HTTP、TCP、UDP 上游池的控制面声明。 不要让热路径每个请求都查注册中心。
tcp.listeners
TCP 原生流量		 数据库、游戏长连接、MQTT TCP、TLS passthrough/SNI。 不要期待这里能做 HTTP 头级别策略。
udp.listeners
UDP、KCP、QCP、CoAP-style		 实时设备、游戏、会话型 UDP 网关。 不要把它包装成协议终端本身。

AI 与 SSE：先保证消息边界

将以下片段合入 proxysss.yaml，修改域名和本地兼容 API 服务地址。AI 路由使用单个 upstream；多上游权重、健康与重试使用通用反代及根 load_balance。供应商账号、密钥和模型选择由上游 New API/sub2api 服务管理。

http:
  plain_bind: 0.0.0.0:80
  tls_bind: 0.0.0.0:443

runtime:
  performance:
    enabled: true
    traffic_profile: small

services:
  ai_proxy:
    enabled: true
    routes:
      - name: llm-edge
        provider: new-api
        match_host: ai.example.com
        path_prefix: /v1
        upstream: http://127.0.0.1:3000
        rewrite_base_path: /v1
        forward_headers: true
        emit_metadata_headers: true

内建 SSE 按下游需求读取，不积累完整事件。TCP_NODELAY 由运行时启用；AI route 没有 transport.flush_interval_ms 等字段。原始 SSE 转 TLS/HTTP2 时先解码 chunked，按终止块或 Content-Length 结束，不等 keep-alive 连接断开。分块元数据行上限 16 KiB、trailer 总上限 64 KiB；trailer 不作为事件数据转发。提前 EOF 报错，已有 gzip 等 Content-Encoding 保留。

查看流式转发与资源所有权

协议与服务配置示例

将需要的片段合并到同一个 proxysss.yaml；合并同名顶层映射，不要重复声明 services、http 或 runtime 键。

域名与路径代理

domains 匹配域名，每条路由直接指定 upstream。/api 去掉前缀，/ws 保留路径；静态和 WebDAV 使用各自的配置面。

services:
  domain_routes:
    - name: main-api
      domains: [example.com]
      path_prefix: /api
      upstream: http://127.0.0.1:8080
      strip_prefix: true
    - name: game-ws
      domains: [example.com]
      path_prefix: /ws
      upstream: ws://127.0.0.1:9000

静态资源与下载

按路径映射 root。支持 GET/HEAD、条件请求、单段与最多 16 段 Range；合法但全部越界返回 416，语法无效的 Range 忽略并返回完整表示。

services:
  static_sites:
    - name: public-assets
      path_prefix: /assets
      root: ./public
      index_files: [index.html, index.htm]
      autoindex: false

注册中心联动

Consul、etcd、Nacos 发现运行在控制面，普通 HTTP/TCP/UDP 只从内存池选上游。此片段声明映射，部署时还需创建名为 api 的反代目标。

services:
  service_discovery:
    enabled: true
    interval_secs: 15
    registries:
      - name: consul-main
        provider: consul
        endpoint: http://consul.service.consul:8500
      - name: etcd-main
        provider: etcd
        endpoint: http://etcd.default.svc.cluster.local:2379
      - name: nacos-main
        provider: nacos
        endpoint: http://nacos.default.svc.cluster.local:8848
    mappings:
      - name: api-from-consul
        registry: consul-main
        service: spring-api
        target: reverse_proxy_route
        target_name: api
        scheme: http

混合下载站点

balanced 是混合负载选项，产品默认仍为 small。cache_control 控制客户端缓存；静态文件没有 not_found_page 或 response cache 配置。热文件缓存与 warm-up 由运行时管理。

runtime:
  performance:
    enabled: true
    traffic_profile: balanced

services:
  static_sites:
    - name: docs
      path_prefix: /docs-site
      root: ./site
      index_files: ["index.html"]
      cache_control: "public, max-age=300"

只读 WebDAV

webdav 是单个配置对象，默认示例关闭写入。使用 auth.enabled、auth.username、auth.password 开启内建 Basic 认证，覆盖 OPTIONS、目录、下载和写操作，密码变更参与热重载，CLI/管理配置显示脱敏；公网使用 HTTPS，认证响应禁止共享缓存。图形化文件管理使用 services.filecloud。

源路径、COPY/MOVE 目标和递归 COPY 子项必须留在 root 内。有效内部链接可用，越界或悬空链接返回 403，PROPFIND 隐藏这些子项。复制到自身/子目录及循环链接会被拒绝；失败的递归 COPY 可能保留已完成的内部文件。FileCloud 同样检查已有目标与新建目标父目录，列表/搜索隐藏不符合边界的子项，上传和重命名 name 必须为单个文件名。两种服务都要求可信运维管理根目录和链接，路径检查不是抵御并发本地链接替换的原子沙箱。

services:
  webdav:
    enabled: true
    path_prefix: /dav
    root: ./dav-data
    allow_write: false
    auth:
      enabled: true
      username: builder
      password: replace-with-a-random-password

WebDAV 与 FileCloud 支持 GET/HEAD、最多 16 段 Range、ETag/日期条件请求。大文件按消费进度读取，每次最多 64 KiB，取消释放资源；公开下载按 cdn_cache_secs 缓存，可覆盖文件不自动标记 immutable，认证下载禁止共享缓存。API/JSON 路径保留字面 + 和 %，下载 URL 只解码一次，中文文件名用 UTF-8 filename* 编码。

PROPFIND 流式返回目录，支持 Depth 0/1；目录默认/infinity 深度返回 403。COPY 支持 0/infinity，MOVE 使用 infinity；Overwrite F 遇到已有目标返回 412。覆盖替换整个目标集合并返回 204，新建返回 201；父集合缺失返回 409，不自动补建。MKCOL 非空请求体返回 415，跨服务器 Destination 返回 502。锁与自定义属性不能由这些方法的支持推断。

TCP 直通

listener 直接指定 upstream，或使用字符串数组 upstreams；不嵌套 routes。适合数据库、游戏和自定义 TCP 协议。SNI 策略另用 tcp.stream_routes。

tcp:
  listeners:
    - name: postgres
      bind: 0.0.0.0:5432
      nodelay: true
      connect_timeout_ms: 2000
      upstream: 10.0.0.12:5432

nodelay 默认 true，同时控制网关接入与上游 socket；显式 false 启用 Nagle 合并，Linux 自动调优不会覆盖它。同名同 bind 的 listener 热更新 nodelay、connect_timeout_ms、protocol 后，新连接读取当前值，已有长连接保持原选项与上游。

KCP 与 QCP 透明 UDP 转发

两个 listener 分别转发到对应服务。session_ttl_secs 控制空闲关联寿命，max_associations 限制关联数量；帧语义与可靠性由上游负责。

udp:
  listeners:
    - name: kcp-gateway
      bind: 0.0.0.0:4000
      session_ttl_secs: 120
      max_associations: 200000
      protocol: kcp
      upstream: 10.0.0.20:4000
    - name: qcp-gateway
      bind: 0.0.0.0:4001
      protocol: qcp
      session_ttl_secs: 120
      max_associations: 200000
      upstreams:
        - 10.0.0.21:4001

MQTT 与 IoT

MQTT over WebSocket 走 HTTP 反代，原生 MQTT 走 TCP，CoAP-style 走 UDP。proxysss 是 broker 前的通用边缘网关。

services:
  reverse_proxy:
    routes:
      - name: mqtt-ws
        hosts: [iot.example.com]
        path_prefix: /mqtt
        upstream: http://127.0.0.1:8083

tcp:
  listeners:
    - name: mqtt-tcp
      bind: 0.0.0.0:1883
      nodelay: true
      upstream: 10.0.0.30:1883

udp:
  listeners:
    - name: coap
      bind: 0.0.0.0:5683
      session_ttl_secs: 30
      max_associations: 50000
      upstream: 10.0.0.31:5683

独立只读监控

monitor 使用独立密码和 monitor:read 会话，仅在 HTTPS 暴露健康、摘要、统计与 SSL 状态。不能复用管理员 bearer token，不能读取配置或执行写操作。

admin:
  monitor:
    enabled: true
    path_prefix: /_proxysss/monitor
    password: "至少 12 位的独立监控密码"
    session_ttl_secs: 43200
    hosts: [monitor.example.com]

管理、只读监控与 /metrics 使用相同 HTTP 统计源。JSON http_requests / Prometheus proxysss_http_requests_total 包含缓存、sendfile、反代、SSE 和 HTTP/1、HTTP/2、HTTP/3；WS/WSS 只计握手，后续消息不重复计数。

JSON http_errors / Prometheus proxysss_http_errors_total 对网关生成或上游返回的 4xx 与 5xx 响应各计一次，例如 404、413、上游 503 和网关 502。它不是纯 5xx 故障指标，也不涵盖所有 socket/正文传输异常；没有形成 HTTP 响应的失败和发送途中中断应结合错误日志检查。

只读 stats 包含网关运行秒数 uptime_seconds、进程 CPU/内存、TCP 会话、UDP 流量、重载、认证失败、脚本错误及 watchdog 计数。ssl.file_validity 与 SNI 条目的同名字段返回证书文件的 not_before、not_after Unix 秒和 valid_now；缺失、超过 1 MiB 或无法解析时为 null。它描述磁盘文件，不代表监听器或云边缘已加载，不暴露文件路径或密钥。

JSON websocket_sessions_total 和 websocket_sessions_active 分别表示进程启动以来成功升级的 WebSocket 会话数和当前活动会话数；Prometheus 使用对应的 proxysss_websocket_sessions_total、proxysss_websocket_sessions_active。失败握手和普通 TCP 不计入，会话结束后活动数下降，重启后累计数归零。

启动时签发失败及周期续期的签发失败、重载失败和加载新证书可并发发送到多个飞书机器人渠道。每个渠道失败最多尝试三次，响应丢失可能重复，重启后无持久化重试队列。Webhook 和可选签名密钥通过环境变量提供，更改进程环境需要重启服务。CLI 手动签发也发送结果通知；签发完成表示证书文件已更新，加载成功表示网关已加载证书，均不代表云产品已部署；on-demand 事件不发送通知。

飞书使用带状态颜色的消息卡片，展示事件、详情、UTC 时间和固定关键词，例如 proxysss SSL certificate_loaded、proxysss SSL cloud_sync_succeeded。可按事件名称、目标名或关键词查找；实际搜索索引取决于飞书客户端。

云同步成功卡片附带云端证书 ID、证书 SAN 域名（含泛域名）及实际同步域名的 HTTPS 核验链接；TLS 验证仅代表发起同步的网络出口。

notifications:
  channels:
    - name: ops
      kind: feishu
      webhook_env: PROXYSSS_FEISHU_WEBHOOK
      signing_secret_env: PROXYSSS_FEISHU_SIGNING_SECRET

域名请求统计默认开启，从站点、路由、证书和监控配置中收集精确域名，也可显式补充；最多 256 项，显式列表优先，超出记录警告，未配置的 Host 不创建指标。按 HTTP 请求计数，WS/WSS 仅计握手，忽略端口且域名大小写不敏感。只读监控 stats 的 domain_requests 是进程内累计次数映射，Prometheus 对应 proxysss_domain_http_requests_total{host="..."}。热重载保留仍在列表中的计数，移除域名、关闭或重启进程会丢弃对应累计值。关闭使用 domain_stats_enabled: false；统计只包含到达 proxysss 的请求，不代表 CDN 边缘访问或命中率。

执行 proxysss -c /path/proxysss.yaml traffic --interval 5，两次读取本机统计，输出 JSON 域名请求增量、每秒速率及当前 WebSocket 连接数。间隔为 1–3600 秒，优先使用回环管理接口，也可通过配置精确域名的本机 HTTPS 只读监控连接；HTTPS 证书必须有效，采样间隔必须短于监控会话有效期，凭据不会输出。采样期间新增或移除的域名不计算，检测到进程变化或计数回退会失败。命令不保存历史，也不增加转发路径的工作；按天统计可使用 Prometheus 持续采集。

monitoring:
  domain_stats_enabled: true
  domain_stats_hosts: [api.example.com, cdn.example.com]

云产品证书同步

配置域名是发现入口：同步查找同一项目中绑定旧证书的其他 DCDN 域名，要求新证书覆盖全部域名；发生冲突、超过 100 个或无法覆盖时停止，写入前再检查绑定。火山 API 不提供条件更新，检查后仍可能发生并发修改。其他产品及手工安装服务器不会自动发现。可选 cleanup_previous: true 在新证书全部部署及出口核验后，清理本目标记录、身份可核实且无 DCDN 绑定的旧实例；首次启用不删除未记录实例，手工安装无法发现。DNS、证书中心和 DCDN 所需操作请参见随包 Markdown 权限指南。

certificate_sync.targets 按目标启停并选择策略；目前实现 volcengine_dcdn。服务每 60 秒检查启用目标的证书变更，失败或部署未完成时重试。 同步成功的目标及证书摘要持久化，重启或发布不会重复同步未变化的证书；升级旧状态首次会核验一次。证书或目标变化后重新同步，手动和外部定时命令仍主动核验。内建 ACME 在现有证书有效、域名及算法匹配且默认设置下剩余不少于 15 天时不会自动续签；手动 issue 是显式触发。导入复用相同证书；成功要求 DCDN 返回 Deployed 且当前网络出口看到的 TLS 叶证书与本地匹配，不能证明全部边缘节点已更新。证书须有效、密钥匹配并覆盖全部域名。失败提醒在同一进程内去重。

certificate_sync:
  targets:
    - name: example-cdn
      enabled: true
      provider: volcengine_dcdn
      cert_path: ./certs/example.crt
      key_path: ./certs/example.key
      domains: [cdn.example.com]
      project: default
      access_key_env: PROXYSSS_VOLC_ACCESS_KEY
      secret_key_env: PROXYSSS_VOLC_SECRET_KEY
      cleanup_previous: false

aliyun、tencent、aws、azure 是预留策略，尚未实现和验证；启用会报错。

服务进程及手动命令需要所引用的环境变量，证书目录需允许创建锁文件；不要把密钥写入 YAML 或 Git。proxysss -c /path/to/proxysss.yaml certificate sync 同步所有启用目标，失败或尚未生效时返回非零。关闭目标不会取消已在途的请求。

certificate list 输出证书目录、证书与密钥文件路径、ACME 状态目录、文件存在状态及有效期和同步目标，不输出密钥内容或凭据；这些路径仅用于本地运维，不进入只读监控 API。手动同步支持重复 --target 名称 或 --all。使用 certificate issue --certificate primary 签发主证书，--certificate additional-1 选择第一个额外证书，重复选项选择多个或使用 --all。DNS-01 通过共享缓存目录中的锁协调跨进程签发，签发成功表示文件更新，网关异步重载、云部署状态另查。HTTP-01 和 TLS-ALPN-01 需要开启写操作和 bearer token 的本机 loopback admin。不同缓存目录或不共享锁的主机不协调。

每月 1 日 04:00（Asia/Shanghai）可由 systemd timer 调用 oneshot service：OnCalendar=*-*-01 04:00:00 Asia/Shanghai、Persistent=true、AccuracySec=1s。service 的 ExecStart 使用上述命令，通过受限 EnvironmentFile 提供凭据；以 systemd-analyze calendar 检查下次时间。也可由支持时区设置的 cron 调用 0 4 1 * *；普通 cron 不补跑停机期间错过的任务。不能把密钥写入 crontab；定时同步现有证书，不强制新建 ACME 订单。

Common combinations

组合网站、代理与流量转发

API 集群

反向代理 + 权重 + 健康检查 + 缓存 + 限流

根 load_balance 选择算法与健康默认值。路由 upstreams 是字符串数组，upstream_weights 按完整地址设置权重。缓存、限流均需 enabled；respect_origin 尊重是否允许缓存，边缘存储时长使用 ttl_secs。仅缓存可共享响应。

load_balance:
  algorithm: weighted
  active_health:
    enabled: true
    interval_secs: 5
    timeout_ms: 1200
    path: /healthz

services:
  reverse_proxy:
    routes:
      - name: api-cluster
        hosts: [api.example.com]
        path_prefix: /
        upstream: http://10.0.0.11:8080
        upstreams: [http://10.0.0.11:8080, http://10.0.0.12:8080]
        upstream_weights:
          "http://10.0.0.11:8080": 3
          "http://10.0.0.12:8080": 2
        cache:
          enabled: true
          behavior: respect_origin
          ttl_secs: 30
          stale_while_revalidate_secs: 30
          stale_if_error_secs: 120
        rate_limit:
          enabled: true
          requests: 200
          window_ms: 1000
          burst: 400
Wildcard TLS

泛域名证书优先走内建 DNS-01

domains 必填。替换示例凭据并保护配置文件权限；REDACTED 不能用于真实签证。

http:
  tls_bind: 0.0.0.0:443
  tls:
    mode: acme_managed
    acme:
      domains: [example.com, "*.example.com"]
      email: "ops@example.com"
      challenge: dns01
      key_algorithm: ecdsa_p256 # 推荐默认；兼容极老旧客户端时改 rsa2048
      dns:
        provider: cloudflare
        credentials:
          api_token: "REDACTED"

内建续期按 renew_interval_hours 检查，默认每 24 小时一次；http.tls.acme.renew_before_days 默认 15，允许 1–365，剩余时间严格小于阈值时进入续期窗口。有效证书默认设置下距到期不少于 15 天时不会新建订单。证书缺失、密钥或域名不匹配、算法变化、自签名或进入到期窗口会申请；管理员仍可手动签发。火山引擎 DNS-01 只清理本次创建的 TXT，保留同名其他记录。

内建 DNS-01 的 credentials 值可写为 env:变量名，创建 provider 时从服务进程环境读取；变量缺失或为空时签发失败。更改环境变量需要重启服务；外部 acme_dns_external 不使用此语法。

内建 DNS-01 先发布本订单全部 TXT，再通过公共 DNS-over-HTTPS 检查每个值可见后通知 CA；需要访问阿里公共 DNS 或 Cloudflare 公共 DNS，最长等待 900 秒，失败时清理本次创建的记录并报告错误。不同地区的 DNS 缓存可能仍有传播延迟。

同一实例需要 ECDSA 和 RSA 两套证书时，可通过 acme.additional 添加独立证书，继承主账户、DNS provider 和检查间隔，使用独立域名、算法和文件路径；certificates 决定 SNI 映射。额外证书要求内建 DNS-01。首次启动可签发缺失文件；热重载新增缺失的 SNI 文件时，先准备文件或重启签发。

http:
  tls:
    mode: acme_managed
    acme:
      challenge: dns01
      domains: [example.com, "*.example.com"]
      directory_production: true
      dns:
        provider: volcengine
        credentials:
          access_key_id: "REDACTED"
          secret_access_key: "REDACTED"
      additional:
        - domains: [example.com, "*.example.com"]
          cert_path: certs/compat-rsa.crt
          key_path: certs/compat-rsa.key
          key_algorithm: rsa2048
    certificates:
      - domains: [legacy.example.com]
        cert_path: certs/compat-rsa.crt
        key_path: certs/compat-rsa.key

Reload + warm-up

热重载与启动预热

配置对象拒绝未知字段，包括禁用服务中的拼写错误和未实现选项；错误会指出配置文件与字段，启动失败，重载则保留正在服务的有效配置。请求头、脚本 env、DNS credentials 与 upstream_weights 是开放映射，可使用自定义键；已有明确支持的别名仍可读取。先运行 proxysss -c proxysss.yaml check-config，再执行重载。

proxysss open config 打开默认配置；proxysss -c /path/to/proxysss.yaml open config 打开指定文件。Windows、macOS 和有图形会话的 Linux 使用系统文件关联；无图形 Linux 使用终端中的 VISUAL、EDITOR 或 vi。文件不存在或无交互终端时返回错误，不创建文件或直接输出可能包含密钥的内容。

Mistakes

常见配置问题

这些不是单个字段的拼写错误，而是会把整个网关越配越乱的思路问题。

误区 1

把所有问题都塞进脚本

脚本适合业务定制，不适合替代 HTTP、TLS、缓存、限流、路由和流量治理这些原生能力面。

误区 2

拿单条 SSE benchmark 当发布结论

项目要求已经明确：后续所有性能优化都要压测，而且要无副作用。只赢单路链路不算赢。

误区 3

一上来就开公网写管理面

默认的 loopback + enable_write_ops=false 是刻意设计的安全姿势。自动化需要时再显式开启。

CDN 回源与安全目录服务

services.static_sites 支持回源令牌、TCP 对端 CIDR、短期 HMAC-SHA256 签名 URL、站点限流和缓存控制。鉴权先于文件缓存、HEAD、Range 与 304；签名资源返回 no-store。目录索引默认关闭，显式开启后支持大小、GMT 时间、安全链接和条目上限；默认隐藏点文件并检查真实路径边界。

源站令牌只鉴别 CDN，访客防盗刷和缓存命中时的授权须在 CDN 边缘执行。阅读完整配置、签名算法与幂等验证说明 →

安全开关与 Windows/macOS/Linux 适配

proxysss config security 输出安全开关、默认值和中文建议；CDN 鉴权与 FTP 策略可独立停用，保留规则。proxysss config performance 只读探测系统版本、I/O 后端和 socket 参数。Windows/macOS 保留 TCP 自动调节，并提供 keepalive、有界 UDP 缓冲；Linux 延续发行版与 CPU 自适应策略。Windows/macOS 保持现有调度，系统适配只作用于 socket；Linux 保留 CPU 自适应数据运行时。runtime.performance 在启动时固定，修改后需重启。

Docker 验证固定使用 proxysss-verify，运行前后清理同名项目容器，报告覆盖写入项目内固定目录。查看完整配置、安全建议和验证边界

管理后台与内置文档

默认在 http://127.0.0.1:7777/ 查看运行状态。后台使用中文导航、表格与表单，原始 JSON 位于可折叠的诊断区。配置写入和配置展示默认关闭。管理监听器与公共监听器均提供 /docs.html；文档模板、样式和交互脚本嵌入单个二进制。

Windows 使用隐藏启动器注册登录自启动。英文与中文安装说明分别位于仓库的 README.md 和 README-CN.md；详细配置见配置指南。

游戏资源与复杂下载

原生静态服务支持单段和最多 16 段 Range，合并重叠区间并流式发送 multipart/byteranges。HEAD 忽略 Range；条件失败返回 412，全部越界返回 416。大文件局部读取不载入整文件，取消释放资源。脚本 API 无需变化。

下载语义与限制 · Linux 优先验证与发布流程

静态虚拟主机

使用 services.static_sites[].hosts 与 path_prefix 按域名分发资源，多站点预热与连接缓存保持隔离。匹配语法、优先级、重载和鉴权边界统一见 CDN 域名隔离指南。

HTTP 流与请求正文的资源边界

http.request_timeout_ms 默认 15000 ms，约束上游连接、响应头等待和响应正文每次无进展等待，不是整个下载或 SSE 的总时长。正文持续到达重新计时，下游暂停读取不计入上游空闲期限；WebSocket 完成 101 后不受 HTTP 正文期限限制。

http.request_body_timeout_ms 默认 30000 ms，约束客户端正文空闲等待，HTTP/3 也用于请求头解析；http.max_request_body_bytes 默认 67108864。超限返回 413、空闲超时返回 408、损坏或长度不符返回 400，失败正文不会交给写入或反代。FileCloud 的 /api/upload 使用独立 max_upload_bytes 上限。值必须大于 0，重载后供新请求使用。入站正文仍按请求缓冲，单请求上限不是进程内存预算，大上传应结合并发和实际内存预算配置。

WebDAV OPTIONS 只列出实际方法，只读配置不列写方法。未提供 LOCK、UNLOCK、PROPPATCH 或完整 DAV class 1/2 合规声明，需要锁和自定义属性的协作客户端应先核对能力。

流式上游地址与 DNS

TCP/UDP listener、stream route 的 upstream、upstreams、upstream_weights 键，以及启用的 FTP 上游，使用 host:port 或 [IPv6]:port，端口 1–65535。例如 game.internal:9000、127.0.0.1:9000、[::1]:9000。域名使用 ASCII，国际化域名先转 Punycode；支持容器内带下划线的名称。不要加 tcp://、udp://、路径或空白。加载时统一校验，管理更新失败不改写文件，失败重载保留旧状态；检查配置不查询 DNS，也不证明源站可达。

UDP 域名在新 association 建立时查询系统解析器，使用首个地址并按 IPv4/IPv6 绑定 socket。最多等待 5 秒，全进程最多 64 个在途解析；超时后底层调用仍占名额直至结束，满额立即失败。已有会话复用 socket，不逐包解析，不因 DNS 更新立即迁移，重建时重新解析；数字 IP 保持直接路径。多后端重试与可达性检查使用上游池及健康策略，UDP connect 本身不证明对端存活。UDP 健康探测 timeout_ms 覆盖解析、绑定、发送及等待回复整个过程。

UDP 会话容量与热更新

session_ttl_secs 从最后一个客户端数据报计空闲时间，后端持续回复不会延长它。reader 在下一个检查点清理过期会话，检查间隔为 TTL、最长 30 秒。

max_associations 同时限制在途创建与仍占资源的会话，0 表示不设上限。名额在首包复制、脚本和 DNS 前预留，创建失败、取消和会话释放后归还；满额拒绝新会话，不挤掉活跃玩家。

同名同 bind 更新 max_associations、session_ttl_secs、protocol 后，新会话最多一秒内读取新值；已有会话保留原 TTL 和上游。降低容量不主动断开旧会话，它们仍占名额，低于新上限后才允许新建。停用或移除 listener 会关闭接收 worker、在途创建和上游会话并释放端口，不是保留 UDP 会话的迁移操作。

动态黑名单持久化

GET /v1/security/blacklist 查询列表；令牌鉴权的 POST /v1/security/blacklist/add 与 remove 要求 admin.enable_write_ops=true。开启 security.dynamic_blacklist.enabled 后，先完成快照文件替换，再发布到内存/DDoS；成功返回 ok=true, persisted=true，写失败返回 HTTP 500 并保留原内存状态。未开启持久化时更新仍在内存生效，返回 persisted=false。后续 HTTP keep-alive、HTTP/2、AI 请求与新 WS 握手执行当前准入策略；既有 WS/TCP relay 不因准入更新被强制中断。ban_secs=0 规范为 1 秒。

每实例只有一个阻塞写入 worker，排队等待异步执行；已交给 worker 的操作不会因客户端断开而撤回，重试前可先查询列表。普通准入与自动 DDoS 封禁不等待文件锁。

文件使用版本 1 JSON，保存原始 UTC 秒/纳秒及 TTL；重启扣除停机时间并保留小数秒，过期封禁不复活，重复保存不延长 TTL。created_at_nanos 省略时为 0。以下仅说明存储格式，不应复制为新的封禁：

{"version":1,"entries":[{"ip":"203.0.113.5","created_at_unix_secs":1789948800,"created_at_nanos":0,"ttl_secs":3600}]}

启用持久化时，未知版本、重复 IP、错误字段、损坏/不可读文件均导致启动失败；缺失文件表示空列表。旧纯 IP 数组缺少期限，须明确时间和 TTL 后迁移，不能静默续成一小时。

每次成功管理更新保存当时采集到的活动表；此后新增的自动封禁在下次管理快照前仅保存在内存。热更新开关/路径影响随后管理请求的保存位置，当前活动表保留；外部文件在进程启动时读取。

快照目录必须支持同目录原子替换。Linux 容器应使用原生 Docker volume 或 Linux 本地磁盘；Windows 主机共享 v9fs 挂载不具备本次验证要求的完整替换可见性，不能承诺并发读取始终存在文件。文件同步后才 rename，但未承诺断电后的目录项事务，也不支持多进程同时写同一快照。

安全状态有效期

独立控制任务每秒回收过期安全状态，无需开启热重载或主动健康。DDoS 与 admin/monitor 登录失败窗口在窗口失效且没有活动封禁时清理；动态黑名单按实际封禁到期回收，活动封禁保留。查询不会删除并发续封的新值。

ban_secs / lockout_secs 按单调时间计算，超大秒数不会触发时间点加法溢出，剩余秒数向上取整；0 秒保留至少 1 秒的原有语义。并发登录失败不会重置已生效的锁定时间。

TCP / UDP 新会话准入

依次执行 services.rate_limit.stream、动态黑名单、security.ddos 和 services.access_control.stream。UDP 被拒绝时丢弃首包，不生成 HTTP 响应。connections 按新 association 计数，同 IP 的 TCP/UDP 共用 stream zone；既有 UDP 数据报不重复扣配额或重新检查准入策略。

策略更新和新增封禁作用于随后准入的会话，已有会话保留到过期、关闭或 listener 移除。数字上游、DNS 与脚本路由规则相同，拒绝发生在脚本和解析前；blocked_requests_total 每次拒绝只计一次。

脚本保护的静态站点

script_only: true（默认 false）排除原生选站、预热和 HTTP/1/TLS/H2 快缓存直出；脚本显式返回 proxysss://static-site/<name> 后仍检查 Host/path、真实 peer、令牌/签名及 HEAD/Range。rewrite_path 保留站点前缀内完整路径，未替换 query 时保留原 query。

spa_fallback: index.html 只接受根内单个文件名，仅在合法目标既非现存文件也非现存目录时回退。目录缺 index 且关闭 autoindex 仍为 403，隐藏路径、越界/悬空链接不触发回退。root 由可信运维管理，不是并发本地写入沙箱。

显式错误页可携带 400–599 的 status：忽略 Range/If-*，只覆盖成功文件响应；直接访问文件仍走普通静态规则。此功能不自动映射上游或运行时异常。

路由授权、响应策略与证书轮换

`reverse_proxy.routes[]`、`domain_routes[]` 和 HTTP 脚本决策可配置 `auth_request`： `{url, timeout_ms: 3000, failure_status: 503, status_map: {"404": 404}}`。 URL 必须是可信运维选择的 HTTP(S) 地址，不能含用户密码或 fragment；不要把未经校验的访客值拼入目标。 核心固定发送 GET，不复制访客 query、头或正文，不跟随重定向，也不读取认证响应正文。 只有 2xx 放行；401/403 默认保留，401 仅透传 WWW-Authenticate；其余状态按显式 status_map 或 failure_status 拒绝。 网络失败、超时、超过 128 个共享在途请求均拒绝，配额满时不排队。timeout_ms 范围 1..30000，包含等待响应头；取消网络 future 会释放名额。 认证在选定路由的缓存、静态文件、主上游和 WebSocket 握手之前执行；原生免策略快路径不会绕过它。 失败响应强制 private, no-store。未提供任意认证响应头导出或脚本 fetch API。

HTTP 脚本可返回 `upstream: "proxysss://response"`、`status`（200..599）、`response_body`（最多 64 KiB）和 `content_type`；204/304 不发送正文。 `response_headers` 的字符串值对所有状态生效；对象必须只选 `value` 或 `from_header`，可加 `statuses` 数组（省略为所有状态，空数组为不添加）。 例如 `{from_header: "x-cache"}` 复制当前响应头。复现 nginx 非 always add_header 时显式使用 `[200,201,204,206,301,302,303,304,307,308]`，不能默认套给错误响应。 不允许通过该接口修改连接、Content-Length、Transfer-Encoding、Trailer 或 Upgrade framing。 脚本 `cache` 使用现有原生缓存结构；`forward_headers` 控制生成转发头；`pass_request_headers`、`pass_request_body` 默认 true，false 不复制访客头或正文，显式 set_headers 最后生效。 `request_timeout_ms`（1..86400000）单独覆盖该 HTTP 路由上游响应头等待和每次正文无进展期限，默认沿用全局值；持续传输不计为总时长超限，WebSocket 只用于握手。 缓存的现有键和 GET 规则保持原有语义，不宣称完整 nginx proxy_cache_key/HEAD 等价。

`http.tls.reject_unknown_sni` 默认 false；启用后必须配置 certificates[].domains，未知名和无 SNI 在 TLS 握手阶段拒绝。 白名单来自配置选择器，不从物理证书 SAN 自动扩张；on-demand 证书不能绕过该白名单。 默认和全部 SNI 证书/私钥都参加热重载指纹。发布配置前逐对解析并核对公私钥，解析后的材料随状态保存，监听启动不重新读取磁盘。 证书续期若先换 cert 后换 key，中间不匹配时保留旧状态和监听器；完整匹配后下一次自动重载才发布新材料。 热重载须启用 runtime.hot_reload；替换证书不承诺所有既有 TLS 连接立即重新握手。

脚本仍是 YAML/内建路由之后的扩展层。需要脚本保护的资源必须使用 script_only 静态站点，或避免创建更早命中的开放 YAML 路由。 脚本初始化失败会保留 YAML fallback；部署前必须测试脚本入口、拒绝规则及真实资源 canary，不能仅以进程启动或 /healthz 判定业务路由就绪。

upstream_method 默认省略，仅普通 HTTP 回源接受大写 GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS/TRACE，不改访客 ctx.method、固定 GET 授权或 WebSocket。HEAD 显式 GET 回源时只取 GET 元数据，identity 保留 Content-Length，HTTP/1、HTTP/2、HTTP/3 前端无正文，HEAD 缓存仍 bypass；非 HEAD 访客显式 HEAD 回源返回空正文及 Content-Length: 0。

响应头对象 append: true 在上游同名字段之后追加独立字段，保留顺序；省略或字符串仍替换。迁移 nginx add_header 时显式声明 append 和状态列表；Set-Cookie 不折叠，cookie_secure 在最终所有字段上逐条生效，framing 禁止项不变。

脚本 compression 省略或 null 时继承全局，显式对象覆盖整个原生策略，enabled:false 可关闭。仅已知 Content-Length、达到 min_length、MIME 合格且不超过 4 MiB 的普通上游响应收集压缩；未知或更大响应继续流式，SSE、206、204/304 和已有 Content-Encoding 不变换。这不等价于完整 nginx 流式 gzip。

合格 identity/HEAD 表示也保留 Accept-Encoding Vary，206 可按 Content-Range 的完整长度判断 Vary 但绝不压缩部分正文；保留全部上游 Vary token 和独立字段。启用源站编码缓存时显式声明 cache.vary_headers:["Accept-Encoding"]；非 identity 源站编码缺该键维度时不存储，流式正文不进入整块缓存。

合格 MIME 的未知长度或大于 4 MiB 表示仍保留 Accept-Encoding Vary，但保持流式、不执行变换，HEAD 不假报压缩编码；已知小于 min_length 的表示不增加该 Vary。SSE 仍不自动增加该 Vary。

HEAD 对合格 GET 表示协商压缩时声明相同 Content-Encoding，不读取正文计算派生长度，因此省略压后 Content-Length；identity HEAD 保留原长度。压缩表征及其 HEAD 元数据将强 ETag 弱化为 W/，已有弱标签不重复弱化，identity、Range 和已有编码保留原 ETag。

RouteDecision.cookie_secure: true（默认 false）逐个为 Set-Cookie 补 Secure，保留重复 cookie、Expires 逗号、HttpOnly 与 SameSite，已有大小写变体不重复添加。上游网络失败生成的 502 也执行路由 response_headers 的状态规则。

聚合请求体预算

http.max_buffered_request_body_bytes 默认 0，限制同 Gateway 跨 HTTP/1、HTTP/2、HTTP/3 与管理 HTTP 的在飞 buffered payload；chunk 复制前预留，容量满立即503。失败/超时/取消归还；成功 Bytes 的所有 clone 最后释放才返还。重载仅改限额而不重建计数，0 模式也计数。1 GiB 单体可搭配 2 GiB 聚合预算并预留系统内存余量。这是payload预算，不是RSS、分配器/解析器/业务复制总量上限，也不是磁盘spool或全链streaming上传。

明文 HTTP 路由与自动 HTTPS 跳转

http.redirect_http_to_https 默认 true：TLS/ACME 或证书域名命中时沿用原生明文 HTTP→HTTPS 308，保留路径和 query。设为 false 后关闭这层提前跳转，HTTP 继续进入已有 YAML/脚本路由，可显式保留独立的 301/302/代理策略。该开关不改变 TLS listener、strict SNI 或 ACME challenge 处理；需要自动跳转时应保留默认 true。

http:
  redirect_http_to_https: false

http.error_pages.enabled=false 完全保留原错误响应正文及头，不应用内置或配置错误页。脚本 proxysss://response 和显式 script static error-page 的正文由路由定义，即使默认错误页开启也不被二次包装；普通原生错误继续按已启用的 error_pages 策略处理。
