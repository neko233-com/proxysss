v1.3.14 测试缓存治理与干净环境复验

2026-11-22 用户要求在功能全部落地后继续发布线上，并严格避免 proxysss 项目长期占用 100 GB 磁盘。v1.3.14 不改变网关转发行为，重点是建立“每次测试前清空项目构建/测试缓存”的强制规则，并从零缓存环境重新完成 Windows、Linux musl 和静态/反向代理性能复验。

100 GB 级缓存来源

目录清理前占用
target/（debug 74.22 GB + release 11.38 GB + 其他目标）86.63 GB
.benchmark/（历史 Linux target、runs、多套构建）54.21 GB
.tmp/0.98 GB
.cache/0.84 GB
dist/、logs/约 0.09 GB

执行 pwsh -NoProfile -File scripts/clean-test-cache.ps1 后，上述项目缓存、根目录 tmp-* / .tmp-* 测试产物、benchmark 日志和本项目 Docker 验证卷全部移除；项目缓存回到 0，D 盘可用空间回到约 1.27 TB。

强制规则

  • 新增 scripts/clean-test-cache.ps1 / scripts/clean-test-cache.sh。默认清理项目本地构建/测试状态，只拒绝绝对路径越界和链接穿越；不执行全局 docker system prune，不影响其他项目。
  • verify-local.ps1、verify-deep.ps1、verify-e2e.ps1、verify-docker-scenarios.ps1、run-all-verify.ps1、benchmark-gateways.ps1 开始前自动调用清理；verify-local.ps1 结束后保留报告和本地包，但删除 target/、.benchmark/、.cache/。
  • AGENTS.md 与验证文档写入：任何 cargo test、cargo build、cargo clippy、Docker 验证、基准或打包前必须清理；测试结束 target/ 与 .benchmark/ 合计低于 5 GB。
  • KEEP_BENCH_ARTIFACTS=1 只为一次明确发布证据保留，收集后立即清理。

干净环境功能复验

  • Windows 本机：425 passed / 0 failed / 0 ignored，22.55 秒，构建目录指向本轮独占的 .tmp/cargo-target。
  • Linux musl：x86_64-unknown-linux-musl，454 passed / 0 failed / 0 ignored，11.68 秒，构建与测试临时目录使用本轮独占 Docker volume。
  • 修复 filecloud::path 测试临时目录同名碰撞的偶发失败；不改变运行时路径边界逻辑。

干净环境性能复验

网关容器 Ubuntu 24.04、linux/amd64、--cpus=1 --memory=2g；HTTP/1.1 keep-alive，16 workers（反向代理 32），3s warmup + 10s 测量，3 轮取中位。

场景v1.3.13v1.3.14变化p50

p99 中位：1KB 静态 2.038 → 2.023 ms，64KB 2.047 → 2.034 ms，反向代理 4.902 → 4.808 ms。64KB 的 -0.78% 落在三轮样本波动内；小文件与反向代理中位吞吐略高。结论是“清缓存、静态链接后性能不降，部分路径略优”，不宣称 nginx 全面胜出或跨主机容量。
