proxysss 使用文档

从 nginx 迁移到 proxysss。

将常见 nginx 配置对应到 proxysss 的 YAML 配置项，逐步迁移网站、静态文件、TLS 和 TCP/UDP 转发。迁移后检查路由、访问控制和实际流量。

先迁最常见场景 再看高级迁移 回 docs 首页
Migration mindset

先记住该把配置写在哪里

你不用先记所有字段，只要先判断这条能力属于 reverse_proxy、domain_routes、static_sites 还是 tcp/udp listeners。没有用户路由命中 / 时，proxysss 才返回只含 GitHub 和 GitHub Docs 的内建欢迎页；业务首页应显式声明 route/static site。

nginx 思路 proxysss 落点 适合什么
server_name + location / services.reverse_proxy.routes 普通整站反代
location /api/ + proxy_pass match.path_prefix + strip_prefix API 前缀代理
同域名多个路径拼成整站 services.domain_routes 站点级编排
stream {} tcp.listeners / udp.listeners 数据库、游戏、MQTT、UDP
Beginner path

先迁最常见的配置

下面这些场景覆盖了大多数第一次迁移的站点。

API prefix

location /api/

services:
  reverse_proxy:
    routes:
      - name: api
        match:
          hosts: ["api.example.com"]
          path_prefix: "/api"
        strip_prefix: true
        upstreams:
          - url: "http://127.0.0.1:8080"
Whole site

整站反代

services:
  reverse_proxy:
    routes:
      - name: app
        match:
          hosts: ["app.example.com"]
          path_prefix: "/"
        upstreams:
          - url: "http://127.0.0.1:9000"
Static site

静态站点

services:
  static_sites:
    - name: homepage
      hosts: ["www.example.com"]
      root_dir: "/srv/www"
      index_files: ["index.html"]
Auto HTTPS

自动 HTTPS

http:
  plain_bind: 0.0.0.0:80
  tls_bind: 0.0.0.0:443
  tls:
    auto_https:
      domains: [wss.example.com]

只给域名就会启用免费的内建 managed ACME，默认正式环境 TLS-ALPN-01 与 ECDSA P-256；无需 certbot、acme.sh、DNS API 或邮箱。域名必须解析到本机且公网 443 可达。极老旧客户端可设 http.tls.acme.key_algorithm: rsa2048；显式 HTTP-01（需 80）、TLS-ALPN-01 和 DNS-01 配置仍完全兼容。

Advanced path

迁移 TLS、TCP 与 UDP 配置

迁移不是只翻译语法，更是把能力放到更合适的网关面。

Domain routes

站点级编排

services:
  domain_routes:
    - domain: "example.com"
      routes:
        - path_prefix: "/"
          service: static:homepage
        - path_prefix: "/api"
          service: reverse_proxy:api
Load balance

集群 + health

load_balance:
  strategy: weighted_round_robin
  active_health:
    path: "/healthz"
    interval_secs: 5
    timeout_ms: 1200
AI / SSE

流式 AI 代理

runtime:
  performance:
    enabled: true
    traffic_profile: small

services:
  ai_proxy:
    routes:
      - name: llm-edge
        transport:
          flush_interval_ms: 0
          tcp_nodelay: true

stream 迁移

Validation

验证迁移结果

真正的迁移完成，应该同时确认配置面、路由视图、能力面和 mixed-load 性能纪律；涉及公网/NIC 延迟时，再从独立 client 主机运行 scripts/benchmark-cross-host-wss.sh 保存原始证据。

proxysss tune linux --apply
proxysss config explain
proxysss config routes
proxysss config nginx-parity --format yaml
scripts/benchmark-ubuntu24-amd64-docker.sh

默认 GitHub Actions CI 只负责全平台二进制打包，禁止任何性能压测 workflow；迁移性能判断在本机或原生 Docker 跑上面的 Ubuntu 24 amd64 mixed-load，模拟结果不冒充物理 x86。v1.3.5 UDP fast path 当前专项结果是 udp-stream 4.045x，旧历史 mixed-load UDP 行不要当成当前结论。

CDN 回源与安全目录服务

services.static_sites 支持回源令牌、TCP 对端 CIDR、短期 HMAC-SHA256 签名 URL、站点限流和缓存控制。鉴权先于文件缓存、HEAD、Range 与 304；签名资源返回 no-store。目录索引默认关闭，显式开启后支持大小、GMT 时间、安全链接和条目上限；默认隐藏点文件并检查真实路径边界。

源站令牌只鉴别 CDN，访客防盗刷和缓存命中时的授权须在 CDN 边缘执行。阅读完整配置、签名算法与幂等验证说明 →

安全开关与 Windows/macOS/Linux 适配

proxysss config security 输出安全开关、默认值和中文建议；CDN 鉴权与 FTP 策略可独立停用，保留规则。proxysss config performance 只读探测系统版本、I/O 后端和 socket 参数。Windows/macOS 保留 TCP 自动调节，并提供 keepalive、有界 UDP 缓冲；Linux 延续发行版与 CPU 自适应策略。Windows/macOS 保持现有调度，系统适配只作用于 socket；Linux 保留 CPU 自适应数据运行时。runtime.performance 在启动时固定，修改后需重启。

Docker 验证固定使用 proxysss-verify，运行前后清理同名项目容器，报告覆盖写入项目内固定目录。查看完整配置、安全建议和验证边界

管理后台与内置文档

默认在 http://127.0.0.1:7777/ 查看运行状态。后台使用中文导航、表格与表单，原始 JSON 位于可折叠的诊断区。配置写入和配置展示默认关闭。管理监听器与公共监听器均提供 /docs.html；文档模板、样式和交互脚本嵌入单个二进制。

Windows 使用隐藏启动器注册登录自启动。英文与中文安装说明分别位于仓库的 README.md 和 README-CN.md；详细配置见配置指南。

迁移原则： 先把一条 reverse_proxy.routes 跑通，再拆 static_sites、ai_proxy、tcp.listeners、udp.listeners，最后补 TLS、health、cache 和 benchmark。这样最容易发现副作用回归。
