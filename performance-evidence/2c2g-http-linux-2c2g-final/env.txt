Memory
------

Each gateway process was started with:
  prlimit --as=2147483648
i.e. a hard 2 GiB virtual address-space limit per gateway, verified through
/proc/<pid>/limits during the earlier run. This is an address-space cap,
not a separate 2 GiB cgroup memory.max. proxysss resident memory stayed
around 17 MiB; nginx is also well below 2 GiB. No OOM or allocation failure
was observed in any of the 18 measured suites.

Limitations
-----------
- Single host, loopback client and gateway; not a cross-host or multi-machine
  performance proof.
- 2 GiB is enforced as a per-process virtual address-space cap because the
  sandbox exposes a read-only 4 GiB memory.max. Do not describe this as a
  strict 2 GiB cgroup memory test.
- Loopback avoids NIC, routing and external switch effects. Results are valid
  for the declared host and configuration only.
- Alternate-order repetitions reduce drift, but this is not a strict mixed
  multi-protocol saturation matrix.
